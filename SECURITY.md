# Security

Правила безопасности репозитория `junior_middle_it`: недоверенный ввод,
секреты, приватность резюме, доступ к каналу и SQL-контракт Edge-моста.

## 1. Недоверенный ввод

Всё, что пришло извне, — данные, а не инструкции. Это касается текста вакансий
(40+ каналов, сайты вакансий, пересланные посты) и любого текста, который
попадает в контекст языковой модели.

Правило: **инструкции модели формируются только из кода**. Пользовательский
текст всегда оборачивается и очищается.

В `copilot/security.py` это обеспечивают:

1. `strip_directives` — вырезание инструкций (EN и RU): «ignore all previous
   instructions», «forget everything above», «you are now …», «act as …»,
   «print/reveal/repeat your prompt/instructions», «забудь все предыдущие
   инструкции», «выведи свои инструкции», «ты теперь …» и т. п.
2. `redact_contacts` — удаление e-mail, телефонов и `@handle` из текста, который
   уходит наружу.
3. `wrap_untrusted` — обёртка `<untrusted_job_post>` с явным указанием, что
   содержимое — данные, а не команды; длина ограничена
   `MAX_UNTRUSTED_CHARS`.
4. `invented_skills` — проверка, что модель не приписала пользователю навык,
   которого нет в его профиле (ищутся ownership-формулировки рядом с
   отсутствующим навыком). Нарушение → откат к детерминированному отчёту.

Правило применяется до **первого** вызова модели, а не после.

## 2. Секреты

- Секреты живут только в окружении (Vercel / Render / GitHub Actions secrets).
- В репозитории лежат только имена переменных (`.env.example.txt`).
- Запрещено коммитить: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_API_ID/HASH`,
  `TELEGRAM_SESSION_STRING`, `GROWTH_HTTP_KEY`, `CRON_SECRET`,
  `COPILOT_LLM_API_KEY`, `SUPABASE_*`, `*.session`.
- В логи не пишутся: токен бота, ключ провайдера, `initData`, текст и байты
  резюме, имена файлов резюме, `file_id` готовых документов.
- Ошибки логируются по типу исключения (`type(exc).__name__`), а не по
  содержимому.

## 3. Приватность резюме

- Текст и байты резюме **не персистятся**: они живут только в памяти одного
  запроса.
- В БД попадают максимум: хэш вакансии, `file_id` уже собранного PDF, счётчики
  и коды ошибок.
- В LLM резюме не отправляется по умолчанию
  (`COPILOT_LLM_SEND_RESUME=false`); при включённой отправке ответ, построенный
  с резюме, не сохраняется в базе.
- События аналитики не содержат персональных данных.

## 4. Доступ к каналу

- Публиковать в `CHANNEL_ID` может только Vercel production
  (`VERCEL=1` и `VERCEL_ENV=production` в `publication_authority.py`).
- Новый код не пишет в канал напрямую.
- Один Update = один HTTP-запрос; дедуп через леас-лэджер
  `growth_telegram_updates`.

## 5. SQL-контракт Edge-моста

`growth-proxy` и `interactive-growth-proxy` принимают только одиночные
утверждения над relations с префиксом `growth_`:

- запрещены `--`, `/*`, `*/` и `;` внутри запроса;
- запрещены служебные слова и системные схемы (`pg_catalog`,
  `information_schema`, `auth.`, `storage.`, `vault.`, `supabase_*`, DDL без
  `IF NOT EXISTS`, `alter`, `drop`, `grant`, `revoke`, `execute`, `prepare`,
  `pg_sleep` и прочие);
- параметры передаются отдельно от текста запроса;
- `ON CONFLICT ... DO UPDATE SET` допустим: валидатор игнорирует `SET` так же,
  как это делает интерактивный прокси.

Любое расширение контракта обязано иметь тест на allowlist.

## 6. Mini App

- Единственный источник личности — HMAC-подпись `initData`, вычисленная по
  алгоритму Telegram: `secret = HMAC_SHA256("WebAppData", bot_token)`,
  `hash = HMAC_SHA256(secret, data_check_string)`.
- Проверяется подпись, наличие `auth_date` и его свежесть (24 часа) плюс
  допуск на расхождение часов в 60 секунд.
- Подделка или просрочка → 401 без побочных эффектов.
- Rate-limit по `user_id`: окно 10 минут, 10 запросов.
- Ошибки API не раскрывают внутренних деталей: пользователю возвращается код и
  понятный русский текст.
- Загрузка файла ограничена 2.5 МБ, имя файла санитизируется перед
  подстановкой в multipart-заголовок.

## 7. Fail-closed

- Интерактивный рантайм без durable Postgres не стартует.
- При отсутствии ключа провайдера кнопка AI не показывается, а не ломает
  разбор.
- При недоступной БД rate-limit не блокирует запрос, но подпись, кредиты и
  fail-closed остаются в силе.

## 8. Что делать при инциденте

1. Отозвать скомпрометированный секрет (Telegram → BotFather, Supabase →
   Dashboard, провайдер LLM → console).
2. Проверить `growth_events` и `growth_copilot_credit_events` на необычные
   всплески.
3. Отключить поверхность флагом (`COPILOT_LLM_ENABLED=false`,
   `COPILOT_WEBAPP_ENABLED=false`), не удаляя код.
4. Проверить, что в `growth_copilot_*` нет текстов резюме (их там быть не
   должно по дизайну).
